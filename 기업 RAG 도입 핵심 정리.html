기업 RAG 도입 핵심 정리

RAG는 AI가 답하기 전에 회사 문서를 먼저 찾아 읽게 하는 방식입니다. 도입의 성패는 모델 선택보다 어떤 질문에, 어떤 문서로, 누구에게 답할지를 정하는 준비에서 갈립니다.

1. 담당자가 먼저 준비할 것

  1. 목표와 사용자 정하기: 풀 문제, 주 사용자, 성공 지표(응답 시간, 정확도, 문의 감소율)를 한 문장으로 정리
  2. 보안 검토와 범위 확정: 개인정보·급여 같은 제한 문서 분류, 외부 모델 사용 가능 여부 합의
  3. 평가 질문 세트 작성: 질문 30개 이상, 근거 문서와 기대 답변, 답하면 안 되는 질문까지 포함 (업로드 전에 미리 준비)
  4. 문서 정리: 구버전·중복 제거, 문서군별 폴더 생성, 파일명 규칙 적용, 조항 구조 정리
  5. 업로드: 서비스가 자동으로 청킹해서 벡터DB에 저장
  6. 챗봇 테스트: 평가 질문으로 검증
  7. 원인별 수정 후 재테스트
  8. 운영: 문서 갱신 담당자 지정, 로그 점검

2. 문서 준비 규칙

  • 폴더 예시: 인사규정_v2025.03
  • 파일명 예시: 휴가관련조항_20250602개정_적용(정규직)_소유(인사).pdf
  • 파일 내부는 "제5조(연차휴가)"처럼 조항 제목이 명확하게 구분되도록 작성
  • 글자를 읽을 수 있는 PDF 사용 (스캔 이미지는 OCR 필요)
  • 개정일·적용 대상·소유 부서는 파일명뿐 아니라 문서 내용이나 서비스 메타데이터에도 가능하면 입력
  • 청킹은 사람이 직접 하지 않습니다. 업로드하면 서비스가 자동으로 나누므로, 담당자는 자동 분할이 잘 되도록 문서 구조를 정리합니다.

3. 챗봇 지침과 제한 정보 처리

  • 대부분의 RAG 서비스에는 챗봇 지침(시스템 프롬프트) 입력·수정 기능이 있을 가능성이 높습니다. 길이 제한, 수정 권한, 문서군별 지침 가능 여부는 서비스에 확인이 필요합니다.
  • 지침 예시: 근거 문서 내용만 답하기, 출처(문서·조항) 표시, 근거가 없으면 "확인되지 않습니다"라고 답하기, 급여 등 제한 정보는 담당 부서 안내
  • "답하면 안 되는 질문"은 업로드 파일이 아니라 평가 질문 세트와 챗봇 지침에서 다룹니다.
  • 지침은 100% 차단을 보장하지 않으므로, 민감 문서는 아예 업로드하지 않거나 권한으로 분리하는 것이 가장 안전합니다.

4. 오답이 나왔을 때: 원인부터 분류

원인 증상 조치
문서 문제 구버전 혼재, 내용 누락, 표가 잘림 문서 수정·교체 후 재업로드
검색·분할 문제 엉뚱한 조항을 찾아옴 서비스의 분할·검색 설정 조정
답변 방식 문제 근거 없이 지어냄, 거절 못 함 챗봇 지침 수정
규정 자체의 문제 규정이 모호하거나 서로 충돌 해당 부서와 규정 정비 협의

수정할 때마다 같은 평가 세트로 재테스트합니다. 하나를 고치다 다른 답이 나빠질 수 있기 때문입니다.

5. 가장 시간이 오래 걸리는 단계: 문서 준비

시간이 드는 작업은 파일명 붙이기보다 아래 항목입니다.

  • 구버전·중복 문서 가려내기
  • 보안 검토와 제한 정보 분류 (여러 부서 협의 필요)
  • 스캔본 OCR 변환
  • 조항 구조 정리
  • 규정 간 충돌 확인

시간을 줄이는 방법: 한두 문서군으로 먼저 시작해 정리 규칙 만들기, 파일명 규칙 단순화와 템플릿화, 문서 소유 부서가 직접 정리하도록 역할 분담, 반복 작업은 일괄 처리 도구 활용

6. 예제 시나리오 (가상): 한빛전자 사내 규정 도우미

  • 회사: 직원 1,200명 제조업, 인사·IT·품질 규정 문의가 하루 약 80건
  • 목표: 6개월 내 반복 문의 40% 감소, 답변에 근거 조항 표시
  • 1차 범위: 인사 규정 + IT 가이드
  • PoC 1차 결과: 검색 정확도 78%(기준 90%), 거절 정확도 70%(기준 95%)
  • 개선: 청크를 조항 단위로 재분할, 구버전 제거, "근거 없으면 모른다고 답하라" 지침 강화 후 재측정

7. 서비스 화면 시안 (직접 설계)

관리자 콘솔을 5개 화면으로 구성했습니다.

  1. 문서 관리: 폴더별 파일, 메타데이터, 처리 상태
  2. 청킹 확인: 조항 단위 분할 결과, 문제 조각 표시
  3. 챗봇 지침: 지침 입력, 옵션, 버전 이력
  4. 평가 테스트: 질문 세트 일괄 실행, 통과·실패 확인
  5. 운영 로그: 질문·실패 현황, 실패 질문을 평가 세트에 추가

설계 핵심: 업로드 단계에서 문제를 미리 잡고, 수정 후 같은 평가 세트로 반복 검증하며, 운영 중 실패한 질문을 평가 세트로 되돌리는 순환 구조입니다.

8. 솔브레인 담당자에게 확인할 항목

  • 지원 파일 형식, 스캔본 OCR 지원 여부
  • 자동 청킹 방식, 설정 가능 범위, 청킹 결과 확인 기능
  • 메타데이터 입력과 폴더(문서군)별 권한 관리
  • 챗봇 지침의 길이 제한·수정 권한·버전 관리
  • 답변의 출처 표시, 로그·피드백 기능
  • 외부 모델 사용 여부와 데이터 보관 위치
  • 관리자 화면 시연(데모)이나 체험 계정 제공 여부

솔브레인 서비스의 실제 기능과 화면은 공개 자료에서 확인하지 못했으며, 이 문서의 서비스 관련 내용은 일반적인 RAG 서비스를 기준으로 한 것입니다. 예제 회사와 수치는 설명을 위한 가상 데이터입니다.
